# AI Infra Notes

**从 LLM、Agent 到多模态模型的训练与推理基础设施学习笔记。**

围绕 **系统原理 → 框架源码 → 最小实现 → 实验验证**，系统学习模型训练、推理引擎、RL 训推协同和 Agent 运行系统，并逐步扩展到语音、图像与视频生成等多模态领域。

Learning AI training and inference infrastructure through systems concepts, source-code walkthroughs, and reproducible experiments.

> 项目建设中：当前优先整理 LLM 与 Agent 训推知识。下列章节与实验为学习规划，完成后逐步补充文章链接和复现记录。

## 为什么建立这个项目

大模型训推涉及模型计算、GPU、分布式通信、数据处理、调度、缓存和服务等多个层次。学习框架时，既需要跑通配置，也需要理解配置背后的数据流、执行过程和性能取舍。

本项目希望沿着几个具体问题建立完整的知识体系：

- **一批数据如何完成一次参数更新？** 理解数据处理、SFT、分布式训练、显存优化和 checkpoint。
- **一条请求如何生成 token？** 理解 prefill、decode、KV Cache、批处理、调度和模型执行。
- **训练与推理如何组成 RL 闭环？** 理解 rollout、奖励计算、参数更新、权重同步和资源布局。
- **一条 Agent 轨迹如何成为训练样本？** 理解工具交互、环境执行、token 边界、训练 mask 和奖励归因。
- **不同模态如何改变系统设计？** 理解多模态预处理、多阶段执行、流式交互和迭代生成的系统需求。

内容以中文为主，保留常用英文术语，面向希望从“会使用框架”深入到“理解系统并能分析问题”的学习者与工程师。

## 知识地图

### 00 · 学习路线与术语

规划目录：`docs/00-roadmap/`

- 先修知识：Python、PyTorch、Transformer、Linux 与基础性能分析。
- 训推系统全景：数据、模型、运行时、硬件与在线服务的关系。
- 术语表与阅读路线：区分算法角色、进程角色和物理资源布局。

### 01 · 系统基础

规划目录：`docs/01-foundations/`

- **模型计算与内存**：张量形状、attention、参数、梯度、优化器状态与激活。
- **GPU 基础**：执行模型、显存带宽、计算能力、访存与通信瓶颈。
- **算子与执行优化**：CUDA / Triton 基础、算子融合、CUDA Graph。
- **分布式通信**：PyTorch Distributed、NCCL、collective、拓扑与同步。
- **性能分析**：时间线、显存峰值、计算/通信重叠与瓶颈定位。

### 02 · 训练系统

规划目录：`docs/02-training/`

- **数据管线**：tokenization、chat template、packing、padding、loss mask。
- **训练与微调**：预训练和 SFT 的共享系统机制，LoRA / QLoRA，离线偏好训练的数据与计算链路。
- **分布式训练**：DDP、ZeRO、FSDP；TP、PP、SP、CP、EP 及组合方式。
- **显存与计算优化**：混合精度、梯度累积、激活重计算、offload。
- **状态管理**：checkpoint、断点续训、格式转换与训练复现。
- **训练性能**：有效 tokens/s、step 时间、数据加载和通信开销。

### 03 · 推理系统

规划目录：`docs/03-inference/`

- **请求生命周期**：请求接收、tokenization、prefill、decode、流式输出。
- **模型执行**：模型加载、attention backend、采样、CUDA Graph。
- **KV Cache**：容量估算、分页管理、分配回收、前缀复用与淘汰策略。
- **调度机制**：continuous batching、chunked prefill、抢占与公平性。
- **分布式推理**：TP / PP / DP / EP、通信开销、prefill/decode 分离与 KV 传输。
- **推理优化**：量化、推测解码，以及不同负载下的收益与代价。

### 04 · RL 训练系统

规划目录：`docs/04-rl-systems/`

- **算法与系统需求**：PPO、GRPO 等算法所需的数据、模型角色和计算步骤。
- **训练闭环**：rollout、奖励计算、参数更新、评估与权重同步。
- **角色与后端**：Actor、Reference、Critic、Reward 的职责，以及不同算法对这些角色的需求。
- **训推资源布局**：共卡、分卡、交替执行，以及控制器与 worker 的协作。
- **参数与数据流转**：权重同步、参数重分片、策略版本和数据缓冲。
- **同步与异步**：策略滞后、样本陈旧度、长尾轨迹和阶段重叠。
- **训推一致性**：tokenization、logprob、数值精度与执行配置。
- **蒸馏系统**：teacher/student 数据流与 on-policy distillation。

### 05 · Agent 训练与运行系统

规划目录：`docs/05-agent-systems/`

- **轨迹建模**：消息、动作、观察、奖励、终止与截断状态。
- **工具与环境**：接口设计、多轮执行、环境隔离、重置与并发。
- **训练样本转换**：模型输出与工具输出的 token 边界、训练 mask、轨迹拼接。
- **可靠执行**：超时、重试、取消、幂等性与失败恢复。
- **长程任务**：上下文管理、轨迹截断、完成判定、结果奖励与过程奖励。
- **运行与评测**：工具等待和模型生成交替时的调度、轨迹回放、调试与端到端评估。

本模块重点连接 Agent 执行过程与训练数据；通用的 RL 更新和权重同步放在上一模块。

### 06 · 在线服务

规划目录：`docs/06-serving/`

- API、流式输出、请求取消与错误处理。
- 路由、负载均衡、准入控制、限流与背压。
- 扩缩容、容错、健康检查与恢复。
- 可观测性、服务目标、端到端延迟与容量分析。

引擎内部调度放在推理模块，服务层的跨实例调度与运维机制放在本模块。

### 07 · 多模态训推

规划目录：`docs/07-multimodal/`，后续逐步扩展。

| 子方向 | 计划学习内容 |
| --- | --- |
| `common/` | 多模态数据加载、解码、预处理、可变长度 batching 与跨模态对齐 |
| `vision-language/` | 图像编码、动态分辨率、视觉 token、视频帧采样与 encoder 缓存 |
| `speech/` | 音频特征与 codec、ASR / TTS、流式音频、实时率与首包延迟 |
| `omni/` | 多模态输入输出、多阶段执行、音视频同步、实时交互与背压 |
| `image-video-generation/` | Diffusion / Flow Matching、DiT、VAE、迭代采样、时空并行与显存优化 |

视频理解与视频生成分别组织；共享硬件、通信和性能分析基础，针对不同生成范式讨论各自的执行和调度机制。

## 实验与内容规范

实验分为两类：**最小实现**用于理解机制，**框架实验**用于验证真实系统中的行为和取舍。

| 实验类型 | 计划示例 |
| --- | --- |
| 最小实现 | 简化 KV Cache 分配器、batch scheduler、toy rollout buffer |
| 框架实验 | 前缀缓存开关对照、batching 参数对照、RL 阶段耗时拆分 |

每项实验记录问题、假设、硬件、模型、依赖版本、完整命令、输入条件和结果，标明“未运行 / 部分运行 / 已运行”。性能评测同时记录负载和质量约束：

- **推理**：输入/输出长度、并发或到达率、缓存状态，以及 TTFT、TPOT、吞吐、尾延迟、错误率和显存。
- **训练**：有效 batch size、有效 tokens/s、step 时间、显存和训练质量。
- **RL / Agent**：rollout、工具与环境执行、奖励、更新、同步的耗时，以及任务成功率、轨迹长度和策略版本。

技术文章围绕明确问题展开，区分通用原理、版本实现、实验观察与推断。源码使用固定 commit 链接，结论提供实际参考资料，不把未运行的代码或计划实验写成已验证成果。
